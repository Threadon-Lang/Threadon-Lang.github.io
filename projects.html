Threadon / Projects

Projects

no registry, no network, just local paths

Why projects

A Threadon project is any directory with a threadon.toml file. The config is deliberately small: a name, a main file, include paths, test paths and local path dependencies. There is no registry, no network fetch and no pip-style install step. A dependency is just another directory on disk.

The standard library is implicit. You never list it as a dependency.

Create one

Create a project and run its generated entry point:

python3 -m threadon init myapp
cd myapp
python3 -m threadon run

init writes threadon.toml, src/main.th and a tests/ directory. Pass --force to overwrite an existing config. Pass --dir DIR to initialise somewhere other than the current directory.

threadon.toml

The generated file uses a narrow TOML subset: sections, quoted strings and arrays of strings. The parser works on Python 3.9 as well as newer versions; it uses tomllib when present and falls back to its own reader otherwise. Inline tables and nested sections are rejected on purpose.

[project]
name = "myapp"
version = "0.1.0"
main = "src/main.th"

[dependencies]

[paths]
include = ["src"]
test = ["tests"]

Paths are relative to the config file. main selects the source used by run and build; include is added to the import search path; test is where threadon test looks for test.th suites.

Commands

CommandWhat it does
python3 -m threadon init [NAME]Write a new threadon.toml and a minimal source tree.
python3 -m threadon add NAME PATHRecord a local path dependency and cache a snapshot of its files.
python3 -m threadon build [FILE.th]Compile the project source to LLVM IR and write the cache artefact.
python3 -m threadon run [FILE.th]Compile if needed, then execute with lli.
python3 -m threadon test [-k PATTERN]Compile and run each discovered test.th; -k filters names.
python3 -m threadon cleanRemove the project compile cache under .threadon/cache.
python3 -m threadon cache pathPrint the user module cache directory.
python3 -m threadon cache listList cached module snapshots.
python3 -m threadon cache clear [--modules]Clear the project cache; with --modules, also clear the user cache.

Local dependencies

Add a dependency with a name and a directory. The name is how you import it; the path is stored relative to your project so the folder can move as a unit.

python3 -m threadon add util ../util
python3 -m threadon run

The dependency's own threadon.toml is read if it has one, so its version and include paths travel with it. Its source files are copied into the user module cache as a snapshot. You can still pass explicit -I DIR flags; those are searched alongside project includes.

No dependency ever downloads code. If a path does not exist, the compiler reports a project error rather than trying a registry.

Lockfile and caches

threadon.lock is plain JSON. It records a hash of the config plus a name, path, version and content hash for each dependency. Commit it if you want that resolution in version control. It is not an enforcement file yet: the compiler does not currently read it to reject a changed dependency.

The compile cache lives in <root>/.threadon/cache. Its metadata records whether native modules were present: when a project switches to or away from a native module, the cached IR is skipped and rebuilt. Cached runs print cached ... so you can tell what happened.

Compatibility

  • Python 3.9 or newer. tomllib is optional; the small parser handles the config format itself.
  • Project discovery walks up from the current directory to find the nearest threadon.toml.
  • If you pass a source file, its directory is used too, so invoking the compiler from outside the project still finds its imports.
  • The bundled standard library is always searched last and cannot be shadowed by an accidental local math.th.
  • Set THREADON_CACHE_DIR to move the user module cache away from ~/.cache/threadon/modules.

Troubleshooting

SymptomFix
no threadon.toml foundRun the command from inside the project, or pass --dir to init.
A dependency import is missingCheck the name in [dependencies], then run cache clear to refresh its snapshot.
A native module changed but the old result is usedRun clean; native projects deliberately bypass the IR cache.
Tests from another project are picked upList the exact directories in [paths] test and use -k to filter.
