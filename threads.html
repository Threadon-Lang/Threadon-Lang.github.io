The thread statement

Threadon lets you spawn OS threads with the thread statement at module level (outside any function). A thread runs a block of code in parallel with the main program.

Syntax:

thread ThreadName() on True:
    # thread body
    print("running on a thread")

The parts:

  • ThreadName — an identifier you choose. It becomes the internal function name and appears in debug output.
  • () — always empty parentheses. Threads take no arguments directly; they capture variables by value from the surrounding scope.
  • on True — a boolean condition. The thread only spawns if this evaluates to True at the point of the statement.
  • The indented block — runs on the new thread if the condition is true.

Module-level threads run before main() starts, in the order they appear in the source file:

thread Initializer() on True:
    print("initializing from module thread")

def main() -> Int32
    print("main sees initialized state")
    return 0
initializing from module thread main sees initialized state

The thread statement is non-blocking. All spawned threads are automatically joined before the program exits.

Capturing variables by value

Threads capture variables from the module scope by value. The thread gets a snapshot of the variable's value at the moment the thread statement executes. Later changes to the variable do not affect the thread, and vice versa.

x: Int32 = 42
thread Capture() on True:
    print("thread sees:", x)
x = 99

def main() -> Int32
    print("main now has:", x)
    return 0
thread sees: 42 main now has: 99

This applies to all types — integers, floats, strings, structs, lists, etc. For lists and structs, the thread gets its own copy of the data structure.

Ending a thread early with thread_exit()

Inside a thread body you can call thread_exit() to stop the thread immediately. It acts like an early return from the thread's function.

thread ExitDemo() on True:
    print("before exit")
    thread_exit()
    print("this never prints")

def main() -> Int32
    print("main continues")
    return 0
before exit main continues

The on condition

The expression after on must evaluate to a Bool. It is checked at the moment the thread statement is reached. If false, the thread body is skipped entirely and no thread is created.

flag: Bool = False
thread Conditional() on flag:
    print("won't run")

def main() -> Int32
    print("no thread was spawned")
    return 0
no thread was spawned

Thread joining and program exit

All threads spawned by thread statements are automatically joined before the program exits. You don't need to call any join function yourself.

The join happens in two phases:

  1. Module-level threads are joined after they complete but before main() starts.
  2. Any threads spawned inside functions (if supported in the future) would be joined after main() returns but before the process exits.

This means the program will wait for all threads to finish before exiting. A thread that runs forever will hang the program.

Multiple threads

You can spawn as many module-level threads as you like. They all run concurrently (subject to OS scheduling).

thread T1() on True:
    print("thread 1")
thread T2() on True:
    print("thread 2")
thread T3() on True:
    print("thread 3")

def main() -> Int32
    print("main done")
    return 0
thread 1 thread 2 thread 3 main done

The order of output from different threads is non-deterministic.

Current limitations

  • Threads are only supported at module level (outside functions).
  • No thread synchronization primitives yet (mutexes, channels, atomics). Shared mutable state between threads is not safe.
  • Threads cannot return values to the parent.
  • No way to wait for a specific thread from inside another thread.
  • Thread stacks are not configurable; they use the OS default.

See the Limits page for more things that don't work yet.
