Containers

functional stacks, queues and maps

What it does

Stacks and queues hold Int32 in a list; the maps add Dict-backed key/value storage with String keys, Int32 values, and the reverse. Threadon passes classes by value and a method call gets a copy of self, so methods either only read the container or return a new one. Reassign the result. The old module-style functions are still available as aliases.

Example

A short program using the module:

import containers

def main() -> Int32
    ages: containers.StringIntMap = containers.empty_string_int_map()
    ages = ages.put("ann", 30)
    ages = ages.put("bob", 40)
    found: containers.IntLookup = ages.get("bob")
    print(found.found)
    print(found.value)
    print(ages.size())
    return 0
True 40 2

Notes and gotchas

  • Stacks are LIFO; queues are FIFO. Popping an empty one returns 0 and the same container.
  • A missing key gives found=False and the zero value (0 or ""), never a KeyError.
  • Put replaces an existing value; removing a missing key returns the same map.
  • Every operation copies the underlying list or dict, so these are meant for small collections.
  • The free functions queue_size(q), push(s, v), string_int_put(m, k, v) and friends still work; they simply call these methods.
