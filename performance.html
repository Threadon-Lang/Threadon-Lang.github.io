How the numbers are measured

The benchmark results time fresh processes, not an in-process loop. That is deliberate: startup is part of what a user pays when running threadon --run. Compilation is reported separately so it does not pollute execution numbers. Every case prints a checksum and the runner verifies that C++, Threadon and Python agree.

vs C++ is median / C++ median. Values below 1 are faster; values above 1 are slower. Timings move between machines, so treat differences near 1 as parity rather than a win.

Before you benchmark

  • Measure the native executable if you care about runtime speed; measure --run if you care about edit-and-run latency.
  • Use the same -O value for every run you compare.
  • Keep debug checks and THREADON_GC_STATS off for timing runs.
  • Run enough samples that the median is stable; the shipped runner defaults to 5 and the recorded table used 3.
  • Compare against the repo compiler, not an older installed package.
